# Матриця контролю доступу — ЛР 4

## Політика відмови

Для чужого ресурсу використовується політика **404 Not Found**.

Причина: звичайний користувач не повинен отримувати підтвердження того, що чужий ресурс взагалі існує. Тому для чужого та неіснуючого ресурсу API має повертати однакову відповідь.

## Матриця доступу

| Дія | Анонім | Reporter | Analyst | Administrator | Власник ресурсу має значення? | Стан реалізації |
|---|---|---|---|---|---|---|
| Перегляд списку `GET /api/incidents` | 401 | дозволено лише власні інциденти | дозволено для аналізу | deny | Так для Reporter | Потрібно реалізувати |
| Пошук `GET /api/incidents/search` | 401 | дозволено лише по власних інцидентах | дозволено для аналізу | deny | Так для Reporter | Потрібно реалізувати |
| Зведення `GET /api/incidents/severity-summary` | 401 | враховуються лише власні інциденти | дозволено для аналізу | deny | Так для Reporter | Потрібно реалізувати |
| Перегляд деталей `GET /api/incidents/{id}` | 401 | власний — allow; чужий — 404 | allow для аналізу | deny | Так | Потрібно реалізувати |
| Створення інциденту `POST /api/incidents` | 401 | allow, власника визначає сервер | allow, власника визначає сервер | deny | Власника призначає сервер | Уже реалізовано у ЛР 3 |
| Update content | 401 | власний — allow; чужий — 404 | deny | deny | Так | Потрібно реалізувати |
| Delete | 401 | власний — allow; чужий — 404 | deny | deny | Так | Потрібно реалізувати |
| Перехід `New → Triaged` | 401 | deny | allow лише якщо поточний статус `New` | deny | Ні | Потрібно реалізувати |
| Перегляд internal comment | 401 | deny | allow після перевірки доступу до батьківського інциденту | deny | Доступ визначається через parent Incident | Потрібно реалізувати |

## Основні правила

- Reporter може працювати тільки зі своїми інцидентами.
- Однакова роль Reporter не означає доступ до ресурсу іншого Reporter.
- Analyst може читати інциденти для аналізу.
- Analyst не отримує автоматичного права змінювати content або видаляти інциденти.
- Analyst може виконувати тільки передбачений перехід `New → Triaged`.
- Administrator не отримує права на всі операції лише через назву ролі. Якщо право прямо не визначено правилами роботи, використовується deny.
- `OwnerUserId`, role, status та інші поля під керуванням сервера не повинні визначатися клієнтом.
- Усі рішення про доступ приймаються на сервері. Приховування кнопки або іншого елемента інтерфейсу не є захистом.
